Guia de publicação 0 / 16
Farol · Supabase + Vercel

Do zip ao site no ar

Dezessete passos, na ordem. Marque conforme for fazendo — a barra no topo mostra onde você está, e a marcação fica salva se você fechar a página.

Antes de começar Você vai precisar de três coisas: Node.js 22.5 ou mais novo instalado (nodejs.org), uma conta no Supabase e uma conta na Vercel. Reserve uns 40 minutos. O pagamento fica para depois — só na Parte 4, quando você for cobrar de alguém.
1

Supabase — o banco de dados

~10 min
Crie um projeto no Supabase

Em supabase.com/dashboard, clique em New project. Escolha a região South America (São Paulo) — o banco perto dos seus usuários deixa tudo mais rápido.

Guarde a senha O Supabase pede uma senha para o banco na criação. Anote num lugar seguro — ela não aparece de novo, e recuperar depois dá trabalho.
Crie as tabelas

Abra o SQL Editor no menu lateral, clique em New query, e cole o conteúdo inteiro do arquivo banco/esquema.sql que está no zip. Clique em Run.

SQL Editor→New query→colar→Run

Deve aparecer Success. No rows returned. Isso é o esperado: o script cria estrutura, não devolve dados. Pode rodar de novo quantas vezes quiser, nada é duplicado.

Confirme que as tabelas apareceram

Vá em Table Editor. Você deve ver oito tabelas: contas, sessoes, clientes, publicacoes, resultados, conexoes, tentativas_login e eventos_pagamento.

Todas vão aparecer com um cadeado ou aviso de RLS enabled. Está certo — é proposital, e a Parte 5 explica o porquê.

Copie as duas chaves

Vá em Project Settings → API. Você precisa de dois valores:

O que copiarOnde está
SUPABASE_URLProject URL — algo como https://abcdefgh.supabase.co
SUPABASE_SERVICE_ROLE_KEYservice_role — a chave secreta, que vem escondida atrás de um botão "Reveal"
A chave errada custa caro Existem duas chaves na mesma tela: anon e service_role. Você precisa da service_role. Ela ignora todas as regras de segurança do banco — por isso só pode existir no servidor. Nunca coloque em arquivo dentro de public/, nunca em variável com prefixo público, nunca mande por WhatsApp ou e-mail.
2

Testar antes de publicar

~5 min
Por que esta parte existe Toda a lógica do sistema eu testei. A conexão com o seu Supabase é a única parte que eu não pude testar sem as suas chaves. Estes três passos fecham essa lacuna em cinco minutos — e é muito mais barato descobrir um problema agora do que depois de publicar.
Descompacte o projeto e abra o terminal nele

Descompacte o zip numa pasta. Abra o terminal e entre na pasta farol. Confira a versão do Node:

node --version

Precisa ser v22.5.0 ou maior. Se for menor, atualize em nodejs.org antes de seguir.

Crie o arquivo de configuração

Copie .env.exemplo para .env.local e preencha as duas chaves do passo 4:

cp .env.exemplo .env.local

Abra .env.local num editor de texto e preencha:

SUPABASE_URL=https://seuprojeto.supabase.co
SUPABASE_SERVICE_ROLE_KEY=cole_aqui_a_chave_service_role

Sem aspas, sem espaço depois do =. O arquivo .env.local já está no .gitignore, então ele não vai parar no GitHub por acidente.

Rode o verificador 
node verificar.js

São 18 checagens contra o seu banco: criação de conta, senha, sessão, isolamento entre agências, filtro de datas, atualização de resultado mensal e exclusão em cascata. O script apaga tudo o que criou — não deixa lixo, e pode rodar quantas vezes quiser.

O que você quer ver no fim:

  18 passaram, 0 falharam

  Está tudo certo. Pode publicar na Vercel.
Se falhar A causa mais comum é o esquema não ter sido rodado (volte ao passo 2). A segunda é chave errada — conferir se copiou a service_role e não a anon. Se persistir, me mande o texto do erro que eu corrijo.
3

Vercel — colocar no ar

~15 min
Suba o projeto para o GitHub

Crie um repositório privado no GitHub e envie o projeto:

git init
git add .
git commit -m "primeira versao"
git branch -M main
git remote add origin https://github.com/SEU_USUARIO/farol.git
git push -u origin main
Repositório privado, sempre Se por qualquer motivo a chave service_role acabar num repositório público, qualquer pessoa lê e apaga o banco inteiro. O .gitignore já protege o .env.local, mas repositório privado é a garantia que não depende de nada dar certo.

Prefere sem GitHub? Dá para publicar direto do terminal com npx vercel — mas com GitHub cada git push vira um deploy automático, e é assim que você vai querer trabalhar daqui em diante.

Importe o projeto na Vercel

Em vercel.com/new, escolha Import Git Repository e selecione o repositório que você acabou de criar.

Não mexa em nada nas configurações de build. Framework Preset fica em Other, e os campos de build ficam vazios. Este projeto não tem build — é Node puro, sem dependência nenhuma para instalar. O vercel.json já diz à Vercel o que fazer.

Ainda não clique em Deploy — vá primeiro para o próximo passo, na mesma tela.

Cadastre as variáveis de ambiente

Ainda na tela de importação, abra Environment Variables e cadastre as duas do passo 4. Se já tiver clicado em Deploy, elas ficam em Settings → Environment Variables do projeto.

Settings→Environment Variables→Add
NomeValorAmbientes
SUPABASE_URLa Project URLtodos
SUPABASE_SERVICE_ROLE_KEYa chave service_roletodos
NODE_ENVproducaoProduction
URL_BASEo endereço do seu site, com httpsProduction

NODE_ENV=producao liga duas proteções: o cookie de sessão passa a exigir HTTPS, e o servidor passa a recusar requisições vindas de outros sites.

A pegadinha que mais trava gente Variável nova só vale no próximo deploy. A Vercel congela a configuração no momento em que o site é construído — é isso que permite voltar a uma versão anterior com segurança. Se você adicionar ou corrigir uma variável depois, precisa clicar em Redeploy; salvar não basta.
Deploy e primeiro teste

Clique em Deploy e espere. Vai levar menos de um minuto — não há dependência para instalar.

Quando terminar, abra a URL que a Vercel te deu. Você deve ver a página de vendas. Depois abra /app — deve aparecer a tela de login.

Crie uma conta de verdade pelo Criar conta, cadastre um cliente e lance uma publicação. Se isso funcionar, o sistema inteiro está funcionando: banco, sessão, plano e diagnóstico.

4

Pagamento — só quando for cobrar

depois
Não faça isso agora O sistema funciona sem pagamento — toda conta nova entra com 14 dias de teste. Deixe esta parte para quando você tiver uma agência querendo pagar. Vender primeiro, cobrar depois, é a ordem que economiza semanas.
Ligue o e-mail de recuperação de senha

Sem isto, quem esquece a senha não tem como voltar — e vai te chamar no WhatsApp. O sistema fala direto com o Gmail, não precisa contratar nada.

A senha da sua conta Google não funciona aqui O Gmail exige uma Senha de app: um código de 16 letras, separado da sua senha, que só existe depois de ligar a verificação em duas etapas. É melhor assim — se um dia o projeto vazar essa senha, ela dá acesso só ao envio de e-mail, e você a revoga num clique sem trocar a sua senha de verdade.
myaccount.google.com→Segurança→Verificação em duas etapas→Senhas de app

Crie uma senha de app, copie as 16 letras e cadastre estas variáveis na Vercel:

EMAIL_MODO=smtp
SMTP_HOST=smtp.gmail.com
SMTP_PORTA=465
SMTP_USUARIO=seuendereco@gmail.com
SMTP_SENHA=as16letrasdasenhadeapp
EMAIL_DE=seuendereco@gmail.com
EMAIL_NOME=Farol

Depois de salvar, Redeploy — como no passo 10.

Para testar: na tela de login, clique em Esqueci minha senha, ponha o seu e-mail e veja se a mensagem chega. Confira também a caixa de spam.

Dois limites do Gmail, para você não ser pego de surpresa Ele entrega umas 500 mensagens por dia — sobra para recuperação de senha, não serve para disparo em massa. E mensagem saindo de @gmail.com para quem não te conhece cai em spam com mais facilidade. Quando tiver domínio próprio, troque EMAIL_MODO para http e use Resend ou Brevo com o domínio verificado: a entrega melhora muito e o remetente passa a ser contato@seudominio.
Por que URL_BASE não é opcional É com ela que o sistema monta o link que vai no e-mail. Sem ela, o link é montado com o cabeçalho Host da requisição — que vem de quem chamou a rota. Alguém poderia fazer sair um e-mail seu, com a sua marca, levando ao site dele.
Crie os três planos no meio de pagamento

No Stripe, Mercado Pago ou Pagar.me, crie uma assinatura para cada plano: Essencial R$ 97, Agência R$ 197 e Estúdio R$ 397. Anote o id de cada preço.

Configure o webhook

Aponte o webhook do provedor para:

https://SEUDOMINIO/api/pagamento/webhook

Copie o segredo de assinatura que o provedor gera e cadastre na Vercel junto com os ids dos preços:

SEGREDO_WEBHOOK=
PRECO_ESSENCIAL=
PRECO_AGENCIA=
PRECO_ESTUDIO=

Depois de salvar, clique em Redeploy — como no passo 10.

Por que isso é o coração da cobrança Quem define o plano de uma conta é essa confirmação assinada chegando do provedor. Nunca um parâmetro de URL, nunca um campo do formulário. O ?plano=agencia que vem da página de vendas só serve para pré-selecionar o plano na tela — não vale nada sozinho.
Ajuste os três pontos marcados no código

Abra src/pagamento.js e procure por AJUSTAR. São três: o mapa de id de preço para plano, onde o provedor coloca a referência da conta, e os nomes dos eventos.

O arquivo já está escrito no formato do Stripe. Se usar Mercado Pago ou Pagar.me, o desenho é o mesmo — mudam o nome do cabeçalho de assinatura e o formato do payload.

Se der errado

consulta
SintomaCausa quase sempre
Página abre mas login dá Erro internoVariável de ambiente faltando ou errada. Confira em Settings → Environment Variables e clique em Redeploy.
relation "contas" does not existO esquema.sql não foi rodado, ou foi rodado noutro projeto do Supabase.
Tudo dá 401 depois de entrarFalta NODE_ENV=producao, ou o site está sendo aberto por HTTP em vez de HTTPS.
permission denied for tableEstá usando a chave anon no lugar da service_role.
Webhook responde Assinatura inválidaSegredo errado, ou o corpo chegou alterado. A tabela eventos_pagamento guarda o corpo recebido para comparar.
Deploy dá erro de buildAlguma configuração de build foi preenchida. Deixe tudo vazio e Framework Preset em Other.
Onde ver o erro de verdade Na Vercel, abra o projeto e vá em Logs (ou Runtime Logs). Ali aparece o erro exato que a função devolveu. Copiar essa mensagem é o caminho mais rápido para eu resolver.
